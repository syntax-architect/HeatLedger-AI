Part 1. Your login question, answered
You are right. Login must be mandatory, and in this zip it is not enforced. I tested it, I did not assume it.
Question
Answer
Is login mandatory?
Yes, always. A plant must never see anything before signing in, and must only ever see its
own organization.
How does a plant
get its own records?
Each customer is an Organization. Every user belongs to one organization. Every table row
carries organization_id. The server reads the organization from the signed login cookie,
never from the URL or body.
What stops URL
changing?
Three layers: (1) the API ignores any organization the caller sends and uses the one from
the login; (2) every lookup is 'WHERE id = ? AND organization_id = ?', so another plant's id
returns 404; (3) Postgres row-level security refuses the row even if the code is wrong.
What is public?
Only the marketing pages, the free check, login and signup, and share or verify links that
carry a long random signed token with an expiry. Nothing else.
How do you know it
works?
An automated test logs in as Plant A and Plant B, tries every route with the other plant's
ids, and fails the build if any call returns data. It also fails if any new route has no login
check.
